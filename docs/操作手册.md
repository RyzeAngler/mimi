# Mimi 完整操作手册

本文是当前原型的标准操作顺序。第一次搭建时必须按顺序执行：先确认供电，再单独确认 I²C，再确认触摸和音频，最后启动 Agent 联调。

## 0. 你将得到什么

完成本文后，系统应达到：

- ESP32-C3 能稳定运行并输出串口日志；
- OLED 显示眼睛和动作表情；
- MPU6050 能识别水平、倾斜和摇晃；
- TTP223 能识别触摸；
- Agent 能在默认 legacy 模式请求火山方舟 LLM，或在 vlm 模式结合摄像头调用本地视觉模型；
- 豆包语音 V3 能产生 PCM；
- MAX98357A 能播放声音；
- OLED 表情与语音从 `speech_start` 同步开始，播放完成后回到默认状态。

## 1. 硬件和软件准备

硬件：

- ESP32-C3 SuperMini；
- 4 针 SSD1306 OLED 128×64；
- MPU6050；
- TTP223 三针触摸模块；
- MAX98357A I²S 功放；
- 3W 8Ω 扬声器；
- 数据 USB 线、面包板和杜邦线。

软件：

- macOS 或 Linux；
- VS Code + PlatformIO IDE；
- Python 3.11+；
- legacy 模式：火山方舟 API Key、可用模型；
- vlm 模式：已部署的 Ollama 或 llama-server 视觉模型服务、带摄像头的本机浏览器；
- 豆包语音 V3 API Key、资源 ID、音色 ID。

先阅读 [接线与供电](wiring.md)。供电接错可能损坏 OLED、MPU6050、ESP32 或功放。

## 2. 物理接线

先只接 ESP32、OLED 和 MPU6050：

| 模块 | VCC | GND | 数据 |
|---|---|---|---|
| OLED | 3V3 | GND | SDA GPIO8，SCL GPIO9 |
| MPU6050 | 3V3 | GND | SDA GPIO8，SCL GPIO9 |

然后接触摸：

| TTP223 | VCC | GND | SIG |
|---|---|---|---|
| ESP32 | 3V3 | GND | GPIO10 |

最后接音频：

| MAX98357A | ESP32 / 电源 |
|---|---|
| BCLK | GPIO6 |
| LRC / LRCLK | GPIO7 |
| DIN | GPIO21 |
| GND | 公共 GND |
| VIN | 按模块规格供电，当前原型优先使用 5V/VIN |
| 顶部 TP1（+） | 扬声器正端 |
| 顶部 TP2（-） | 扬声器负端 |

你这块 MAX98357A 模块正面朝上、文字朝向自己时，底部焊盘从左到右是：
`LRC、BCLK、DIN、GAIN、SD、GND、VIN`。不要按焊盘顺序把 GPIO6、GPIO7、GPIO21 依次相邻连接；必须按管脚名称连接。

MAX98357A 的 I²S 信号是 3.3V 数字信号，功放 `VIN` 是供电输入，不能混淆。扬声器两端都接功放，不要把扬声器负端接 GND。

面包板的两侧电源轨可能没有连通。不要假设红色就是 5V、蓝色就是 GND，也不要根据杜邦线颜色判断电压。上电前用万用表确认 3V3、5V 和 GND。

## 3. 配置固件网络

复制配置模板：

```bash
cd /path/to/mimi
cp firmware/config/network_secrets.h.example firmware/config/network_secrets.h
```

编辑 `firmware/config/network_secrets.h`：

```cpp
#define MIMI_WIFI_SSID "你的WiFi名称"
#define MIMI_WIFI_PASSWORD "你的WiFi密码"
#define MIMI_AGENT_HOST "运行Agent的电脑局域网IP"
#define MIMI_AGENT_PORT 8765
#define MIMI_AGENT_PATH "/"
#define MIMI_DEVICE_ID "mimi-c3-01"
```

`MIMI_AGENT_HOST` 不能填写 `127.0.0.1` 或 `localhost`，因为 ESP32 需要访问电脑的局域网地址。电脑和 ESP32 必须连接同一局域网。

查看 macOS 局域网地址：

```bash
ipconfig getifaddr en0
```

如果使用其他网络接口，可执行：

```bash
ifconfig
```

`network_secrets.h` 已被忽略，不能提交到公开仓库。

## 4. 配置 Agent

进入 Agent 目录并创建虚拟环境：

```bash
cd /path/to/mimi/agent
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
cp .env.example .env
```

默认 legacy 模式编辑 `agent/.env`：

```env
MIMI_AGENT_HOST=0.0.0.0
MIMI_AGENT_PORT=8765
MIMI_LOG_LEVEL=INFO

ARK_API_KEY=你的方舟APIKey
ARK_MODEL=你的已开通模型或推理接入点
ARK_MAX_TOKENS=24
ARK_CONTEXT_TURNS=10

VOLCENGINE_API_KEY=你的语音APIKey
VOLCENGINE_RESOURCE_ID=你的语音资源ID
VOLCENGINE_VOICE_TYPE=你的音色ID

MIMI_AUDIO_SAMPLE_RATE=16000
MIMI_AUDIO_CHANNELS=1
MIMI_AUDIO_SAMPLE_WIDTH=2

```

注意：

- `ARK_API_KEY` 与 `VOLCENGINE_API_KEY` 不是同一个配置；
- `ARK_MODEL` 必须是当前账号已开通的模型或推理接入点；
- `ARK_CONTEXT_TURNS` 默认 10，表示最近 10 轮完整对话；
- system prompt 每次都存在，不计入 10 轮；
- 不要把 `.env`、API Key 或接口报错截图提交到仓库。

### 4.1 使用视觉模式

两种模式都需配置豆包 TTS；视觉模式不要求 `ARK_API_KEY` 或 `ARK_MODEL`。先部署本地视觉模型，再在 `.env` 中选择一条路径。以下模型名称是示例，应替换为服务端实际名称。

Ollama 图片路径：

```env
MIMI_RUNTIME_MODE=vlm
MIMI_VLM_PROVIDER=ollama
MIMI_VLM_BASE_URL=http://127.0.0.1:11434/v1
MIMI_VLM_MODEL=minicpm-v-4.6-local
```

llama-server 视频路径：

```env
MIMI_RUNTIME_MODE=vlm
MIMI_VLM_PROVIDER=llama-server
MIMI_VLM_BASE_URL=http://127.0.0.1:8080/v1
MIMI_VLM_MODEL=minicpm-v-4.6
MIMI_VLM_VIDEO_WINDOW_SECONDS=1
```

llama-server 需加载支持视觉的模型与对应 `--mmproj`，服务端环境需提供视频处理工具 `ffmpeg`、`ffprobe`。当前从源码 editable 安装运行；wheel 静态页面打包尚待修复。其他采集参数见 [Agent 使用说明](../agent/README.md)。

## 5. 先验证 Agent，不连接设备

### 5.1 运行单元测试

```bash
cd /path/to/mimi/agent
source .venv/bin/activate
python -m pytest -q
```

普通测试不调用真实模型或云端 TTS；WebUI 测试需要在本机临时端口监听，在线 TTS 测试默认跳过。

### 5.2 在线验证 legacy 的 LLM → TTS → WAV

```bash
MIMI_RUN_LIVE_TESTS=1 PYTHONPATH=src python -m pytest -q -m integration
PYTHONPATH=src python examples/pipeline_smoke.py
afplay cache/pipeline-smoke.wav
```

如果 TTS 返回 `requested resource not granted`，说明资源 ID、账号权限或音色没有匹配，不是 ESP32 接线问题。

## 6. 启动 Agent 服务

保持以下终端一直运行：

```bash
cd /path/to/mimi/agent
source .venv/bin/activate
PYTHONPATH=src python -m mimi_agent.application.server
```

成功日志类似：

```text
Mimi Agent 已启动，监听 ws://0.0.0.0:8765，LLM provider=ark model=你的模型。
```

服务启动顺序必须早于 ESP32 连接。否则 ESP32 会先连接失败，并按照重连间隔再次尝试。

Agent 日志：

- `agent/logs/interaction.log`：动作、LLM 输入、LLM 输出和语音完成记录；
- `agent/logs/sensor.log`：ESP32 遥测；
- 终端：连接状态、LLM/TTS 错误和时序信息。

日志是自然语言记录，不应包含 API Key。

### 6.1 打开视觉控制台

vlm 模式启动后打开 `http://localhost:8090`，点击“启动摄像头”并授权。Ollama 在触发时采集当前 JPEG；llama-server 在浏览器滚动录制中取最近完成的片段，需等待首段视频就绪再点击“立即分析”。默认采集最长边 320px、最高 4fps，视频窗口约 1 秒。

页面应显示模型回复、耗时及语音状态。没有 ESP32 时语音显示为跳过；设备连接后，可用手动分析或触摸、倾斜与摇晃触发。当前没有定时推理，模型输出为自然语言。忙时手动请求被拒绝，传感器事件只保留最新一个。

Ollama 摄像头不可用时，传感器事件可仅用文本推理；llama-server 没有视频时显示错误，不请求模型。VLM 出错不自动调用 Ark；需要回退时设置 `MIMI_RUNTIME_MODE=legacy` 并重启。

## 7. 编译和烧录固件

如果终端没有 `platformio`：

```bash
export PATH="$HOME/.platformio/penv/bin:$PATH"
platformio --version
```

编译：

```bash
cd /path/to/mimi
platformio run --environment esp32-c3-supermini
```

查看设备串口：

```bash
platformio device list
```

烧录：

```bash
platformio run --target upload \
  --environment esp32-c3-supermini \
  --upload-port /dev/cu.usbmodemXXXX
```

VS Code 用户也可以使用 PlatformIO IDE 的 Build、Upload 和 Monitor 按钮。PlatformIO CLI 不是 VS Code 插件列表中的独立插件，PlatformIO IDE 会在项目任务中调用它。

如果上传提示端口 busy：

1. 关闭另一个 PlatformIO Monitor 终端；
2. 关闭其他串口工具；
3. 确认没有正在运行的上传任务；
4. 重新执行上传。

## 8. 启动串口监视器

```bash
platformio device monitor \
  --port /dev/cu.usbmodemXXXX \
  --baud 115200
```

按 ESP32 的 RESET 后，应看到：

```text
Mimi firmware booting
I2C candidate pins: SDA=8, SCL=9
I2C scan started
TTP223 ready: SIG=GPIO10 active=HIGH debounce=50ms
I2S player ready: BCLK=6 LRCLK=7 DOUT=21
Mimi firmware ready
```

如果模块接线正确，还应看到：

```text
I2C device found at 0x3C
I2C device found at 0x68
OLED ready at 0x3C
MPU6050 ready at 0x68, WHO_AM_I=0x68
```

## 9. 联调验收顺序

### 9.1 OLED

水平放置设备：

- OLED 显示默认眼睛；
- 默认平静表情每 5 秒触发一次友好眨眼；
- 不依赖 Agent 也应工作。

### 9.2 MPU6050

每次只做一个动作，并等待状态稳定：

| 操作 | 串口状态 | 预期表情 |
|---|---|---|
| 水平静置 | `state=level` | `mood=happy pos=center` |
| 向左倾斜 | `state=tilt_left` | 注视 west |
| 向右倾斜 | `state=tilt_right` | 注视 east |
| 向前倾斜 | `state=tilt_forward` | 向前方向表情 |
| 向后倾斜 | `state=tilt_backward` | 向后方向表情 |
| 晃动 | `state=shaking` | 眩晕/困惑动画 |

串口每 250 ms 输出一行 IMU 诊断，常用字段：

- `ax/ay/az`：加速度，单位 g；
- `gx/gy/gz`：角速度，单位 dps；
- `roll/pitch`：滤波后的姿态；
- `state/behavior`：识别状态和行为模式；
- `visual`：`idle`、`thinking`、`speaking` 或 `draining`；
- `oled`、`mood`、`pos`、`effect`：显示状态。

水平静置时 `az` 应接近 `+1.00g`，`ax/ay` 接近 0，角速度接近 0。小幅抖动属于正常传感器噪声。

### 9.3 TTP223

触摸模块时应看到：

```text
touch: pressed pin=10
touch: released
```

当 Agent 在线，触摸会进入语音同步链路，而不是立即提交最终触摸表情。

### 9.4 Agent 连接

固件日志：

```text
Agent WebSocket connecting to ws://192.168.x.x:8765/
Agent WebSocket connected
Agent hello acknowledged
```

Agent 终端应能看到设备连接日志。两端必须在同一局域网，电脑防火墙必须允许 TCP `8765`。

### 9.5 LLM、TTS 和声音

触摸或晃动后，完整闭环通常包含：

```text
Agent motion event: {...}
motion thinking event=evt-... until speech_start
Agent motion ack event=evt-... will_speak=yes
Speech start id=... rate=16000 player=ready
reaction speaking event=... visual=motion
Speech end id=...
Speech playback drained
reaction playback complete event=...; returned to idle
```

这几行分别表示：动作发出、OLED 思考态、Agent 接受、第一块 PCM 到达、表情/声音开始、Agent 发送完 PCM、I²S 播放尾部结束、恢复空闲。

### 9.6 视觉与播放回执

分别验证所选 provider 的手动分析和设备事件。视频路径需等待首段录制完成。当前固件在 hello 中声明 `speech_ready` 和 `speech_playback_end`；VLM 语音链路收到就绪回执后发送音频，收到播放完成回执后页面显示完成。旧固件没有声明能力时，页面只确认发送完成，不能据此确认扬声器已播放。

连续执行两次不同动作或手动分析，确认模型回复与声音都可恢复；重复回复可能被抑制，不应以相同文本重复播放作为验收标准。

## 10. 正确的日常启动顺序

每次使用按以下顺序：

1. 检查模块没有短路，确认 3V3、5V、GND；
2. 连接 ESP32 USB，但先不要让设备反复重启；
3. 视觉模式先启动本地模型，再启动 Agent、打开控制台并授权摄像头；legacy 直接启动 Agent；
4. 打开 PlatformIO Monitor；
5. 按 ESP32 RESET；
6. 等待 `Agent WebSocket connected`；
7. 先测试 OLED 和触摸；
8. 再测试倾斜/摇晃；
9. 最后测试扬声器音量和连续两次语音；
10. 停止时先按 `Ctrl+C` 关闭 Agent，再关闭串口监视器，最后拔掉 USB。

不要在语音播放过程中反复拔插功放供电。需要重新烧录时，先关闭 Monitor，否则串口会被占用。

## 11. 故障排查

### 视觉页面无法打开或没有模型回复

确认 `MIMI_RUNTIME_MODE=vlm`，使用源码 editable 安装，并在运行 Agent 的电脑打开 `http://localhost:8090`。检查本地模型服务、实际模型名称与 `/v1` 接口地址是否一致。浏览器应允许摄像头，视频路径需等待首段录制完成；查看页面错误和 Agent 日志区分媒体不可用、推理超时与模型响应错误。

### 页面有回复但没有声音

检查 ESP32 是否已上报事件或遥测并被 Agent 识别、TTS 配置是否有效。无设备时跳过语音；空回复、含 `something` 的回复及相邻重复回复会被抑制。`sent_unconfirmed` 仅表示音频发送完成、缺少播放确认；需要确认实际播放时使用支持回执的最新固件。

### `pio` 或 `platformio: command not found`

```bash
export PATH="$HOME/.platformio/penv/bin:$PATH"
platformio --version
```

也可以直接使用 VS Code PlatformIO IDE。

### I²C 扫描不到设备

检查：

1. OLED/MPU6050 的 VCC 是否接 3V3；
2. 所有 GND 是否共地；
3. SDA 是否 GPIO8，SCL 是否 GPIO9；
4. 面包板两侧电源轨是否实际连通；
5. 杜邦线是否插在同一排孔；
6. 如果当前开发板原理图使用另一组引脚，再单独验证 GPIO4/5；
7. OLED 是否为 `0x3C`/`0x3D`，MPU6050 是否为 `0x68`/`0x69`。

### OLED 扫描到了但不显示

确认启动日志包含 `OLED ready`。如果有地址但无画面，检查 OLED VCC、GND、SDA、SCL 是否对应，避免把 `SDA` 和 `SCL` 反接。屏幕黑但 I²C 正常时，先按 RESET。

### MPU6050 前后方向反了

在 [firmware/config/motion.h](../firmware/config/motion.h) 调整 `MPU6050_PITCH_SIGN`。不要修改 `gaze_from_tilt()` 或在多个地方重复取反。

### 触摸没有反应

先看 `TTP223 ready`，再看触摸时 SIG 是否真正输出高电平。当前固件使用 GPIO10、active high、50 ms 消抖。若模块是低电平触发，应修改 `TOUCH_ACTIVE_HIGH` 后重新烧录。

### 有 `Speech start` 但没有声音

按顺序检查：

1. `I2S player ready` 是否出现；
2. MAX98357A `VIN` 是否得到正确电压；
3. GND 是否共地；
4. BCLK/LRC/DIN 是否对应 GPIO6/7/21；
5. 扬声器是否接在 `+/-`，而不是接 GND；
6. 音频模块的 `SD` 是否处于使能状态；
7. `Speech end` 后是否出现 `Speech playback drained`。

### 只有第一次动作有反应

最新固件要求第一次动作结束后出现：

```text
reaction playback complete event=...; returned to idle
```

如果没有出现，固件仍处于 `speaking` 或 `draining` 状态。关闭串口监视器后重新烧录最新代码，再测试连续两次动作。

### Agent 没有日志

检查：

- Agent 服务是否仍在运行；
- 固件的 `MIMI_AGENT_HOST` 是否为电脑局域网 IP；
- ESP32 和电脑是否在同一 Wi-Fi；
- macOS 防火墙是否阻止 8765；
- Agent 是否在启动时因密钥或资源配置失败。

### TTS 返回 403 `requested resource not granted`

资源 ID 没有授权给当前账号，或资源 ID 与音色不匹配。重新确认 `VOLCENGINE_RESOURCE_ID`、`VOLCENGINE_VOICE_TYPE` 和控制台权限。

### 上传提示端口 busy

关闭 PlatformIO Monitor、VS Code 其他串口任务和其他串口工具，再重新上传。不要同时打开两个程序独占 `/dev/cu.usbmodemXXXX`。

## 12. 清理运行产物

源码发布时不提交以下目录：

- `.pio/`、`.pio-core/`；
- `agent/.venv/`；
- `agent/cache/`、`agent/logs/`；
- `.pytest_cache/`、`__pycache__/`；
- `firmware/config/network_secrets.h`、`agent/.env`。

只清理 PlatformIO 构建目录：

```bash
platformio run --target clean
```

重新运行测试或示例会自动生成必要的 Python 缓存、日志和音频目录。
